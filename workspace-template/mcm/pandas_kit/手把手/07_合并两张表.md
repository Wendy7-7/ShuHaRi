# 第 7 课：合并两张表（对应 Day 10）

目标：把"成绩表"和"队伍信息表"拼成一张表。
配套：`data/level2_scores_raw.csv`、`data/level2_teams_raw.csv`

---

## 7.1 先看看两张表分别有什么

```python
import pandas as pd

scores = pd.read_csv("data/level2_scores_raw.csv")
teams = pd.read_csv("data/level2_teams_raw.csv")

print(scores.head(3))
print(teams.head(3))
```

```
scores:  team_id  year  problem  score     ← 有成绩，没有专业和学校
teams:   team_id  school  major  region    ← 有学校专业，没有成绩
```

**目标：按 `team_id` 把右边三列接到左边去。** 这个"按哪一列对齐"的列，叫**键（key）**。

---

## 7.2 第一次合并（先看看不清洗会发生什么）

```python
merged = scores.merge(teams, on="team_id", how="left")
print(len(scores), len(merged))
print(merged.isna().sum())
```

**输出：**

```
16 17
school    3
major     3
region    3
```

两个问题同时暴露了：

### 问题一：行数从 16 变成 17

因为 teams 表里 `T16` 出现了两次（重复键），于是 scores 里 T16 那条成绩被复制成了两行。

### 问题二：有 3 行没对上（school/major/region 是缺失）

因为 scores 里的 `t02`（小写）、`T03 `（带空格）、`t09`（小写），在 teams 里找不到对应写法。

**这就是为什么必须先清洗键。**

---

## 7.3 正确做法：先统一键，再去重，再合并

```python
for d in (scores, teams):
    d["team_id"] = d["team_id"].str.strip().str.upper()
```

> 这个 for 循环的意思：对 scores 和 teams **各做一次**同样的处理。
> 比写两遍省事，也避免漏改一个。

```python
print(teams.duplicated(subset="team_id").sum())   # 1，先确认有重复
teams = teams.drop_duplicates(subset="team_id")

merged = scores.merge(teams, on="team_id", how="left", validate="many_to_one")

print(len(scores), len(merged))     # 16 16
print(merged.isna().sum())          # 全是 0
print(merged.head())
```

现在：行数没变，没有缺失，合并成功。

---

## 7.4 how 到底怎么选

| 写法 | 含义 | 结果 |
|---|---|---|
| `how="left"` | 左表（scores）的行全保留，对不上的填空 | 不丢成绩，可能有空 |
| `how="inner"` | 只留两边都有的键 | 对不上的成绩被**直接删掉** |
| `how="right"` | 右表全保留 | 很少用 |
| `how="outer"` | 两边的键全留 | 两边都可能有空 |

**默认优先用 `left`**：你不会悄悄丢数据，而且缺失会被 `isna()` 检查出来。
用 `inner` 的风险是：键没清洗干净时，它把对不上的行**默默删掉**，你还以为一切正常。

**论文里可以这么写**："We used a left join to retain all score records; no unmatched keys were found."

---

## 7.5 validate：让错误当场暴露

```python
validate="many_to_one"
```

意思是"我声明：左边可以重复，右边每个键只能出现一次"。
如果右边有重复键，**直接报错**，而不是给你一张悄悄膨胀的表。

| 场景 | 该用什么 |
|---|---|
| 成绩表 + 队伍信息表 | `many_to_one` |
| 两张表键都唯一 | `one_to_one` |
| 不确定 | 先不加，靠打印行数检查 |

**新手建议：合并后必做两件事——打印前后行数、打印缺失数。**

---

## 7.6 两边列名不一样怎么办

验收数据里就是这样：左表叫 `Team`，右表叫 `team`。

```python
merged = df.merge(info, left_on="Team", right_on="team", how="left")
```

`left_on` = 左表的键列名，`right_on` = 右表的键列名。

合并后两列都会保留，可以删掉多余的那个：

```python
merged = merged.drop(columns=["team"])
```

## 7.7 上下拼接：concat（顺便学，别和 merge 混了）

如果是"2025 年的表"和"2026 年的表"，列结构完全一样，要**上下接起来**：

```python
all_data = pd.concat([df2025, df2026], ignore_index=True)
```

- `merge` = 左右拼（加列）
- `concat` = 上下拼（加行）

`ignore_index=True` 让行号重新排，不然会出现两个 0 行、两个 1 行。
